## Key decisions

### Keyboard path
- **Skip link.** `<a class="skip-link" href="#main">Skip to main content</a>` is the first child of `<body>`. It is off-screen until `:focus`, then fixed top-left, ink pill, 44px high, above everything (`z-50`). `<main id="main" tabIndex={-1}>` is rendered by each page through one `Page` wrapper so the target exists everywhere.
- **Route focus.** `RouteFocus` listens to `usePathname()` and focuses the `h1` (`tabIndex={-1}`, `outline: none`) after navigation, but not on first load. This keeps Next.js client navigation from leaving focus on a removed link.
- **Order.** Every screen is reviewed against DOM order. The only layout that can disagree is the sticky phone bar and the side panel. Both stay last in the DOM when they are visually last. No CSS `order` is used to move interactive elements.
- **Drawer.** `CalcDrawer` already uses `<dialog>` with `showModal()`, which gives the focus trap and Esc. The keyboard spec asserts return of focus rather than re-implementing it.
- **Export control.** Already `aria-disabled`. A test asserts it is in the tab order and does nothing on Enter when unapproved.
- **Toast.** Stays `role=status`, gets a Dismiss button that is the next tab stop after the editor block. The toast does not take focus.

### Focus ring and round buttons
The base-layer rule in `globals.css` is `:focus-visible { outline: 2px solid accent; outline-offset: 2px; border-radius: inherit }`. Browsers draw `outline` following `border-radius` in current Chromium, Firefox and Safari 16.4+, so the square ring seen on round buttons comes from two causes:
1. `border-radius: inherit` on `:focus-visible` replaces the element's own radius with its parent's (square) when the utility class loses the cascade or the element has no radius of its own.
2. Parents with `overflow-hidden` clip the offset outline.

Fix: remove `border-radius: inherit` from the base rule. Keep the 2px outline. Controls that need a ring shape already carry their own `rounded-*` class. For `label`-wrapped inputs (`Dropzone`), use `:has(:focus-visible)` on the label so the ring follows the label's radius. Clipping: wrappers with `overflow-hidden` get `outline-offset: -2px` through a `.focus-inset` class. `focus-ring.spec.ts` loops over all `.rounded-full` focusables on each screen and asserts `getComputedStyle(el).borderRadius` is not `0px`, that outline is `2px solid rgb(91, 61, 245)`, and that the element's bounding box fits its clipping ancestors.

### Axe and contrast
- **Scan helper.** `scanScreen(page, name)` runs `new AxeBuilder({ page }).withTags(['wcag2a','wcag2aa','wcag21a','wcag21aa','wcag22aa']).analyze()`, drops waived rules (a waiver is `{ rule, screen, reason }`, an unused waiver fails), logs moderate and minor, and fails on `serious` and `critical` with the rule id, selector and help URL.
- **Screens.** Reached in a table: `inbox-empty`, `inbox-list`, `notice-view`, `notice-view-line-selected`, `confirm-form`, `calc-drawer-open`, `exorcise-draft`, `exorcise-approved`, `upload-error`, `notice-unsupported`. Each runs at 1440×900 and 390×844. `notice-view-line-selected` also runs at 820×1180 for the tablet drawer.
- **Animations.** The scans run with reduced motion emulated off for the tests that check animation, and on for the axe scans so the glow does not make axe sample mid-animation colours. A separate scan with `animations` on runs for `notice-view` and asserts the same result, because axe reads the computed colours at that instant and the glow is only a shadow.
- **Fog.** Axe may report `color-contrast` over the fog. Fog is behind the text and neutral at 12 to 16% alpha, so the check is expected to pass. If axe flags a pair, the fog opacity is checked against the ratios first and a waiver is the last resort.
- **Contrast test.** `a11y-contrast.test.ts` reads token values from `globals.css` (reusing the parser from `tokens.test.ts`), computes relative luminance per WCAG 2.x (sRGB linearisation), and checks a table of `{ fg, bg, documented, min }`:

| Pair | Documented | Min |
|---|---|---|
| ink on surface | 17.9 | 4.5 |
| text-secondary on surface / canvas | 8.0 / 7.1 | 4.5 |
| text-muted on surface / canvas | 5.4 / 4.7 | 4.5 |
| accent on surface / canvas | 6.1 / 5.4 | 4.5 |
| surface on accent | 6.1 | 4.5 |
| haunt fg on bg | 5.5 | 4.5 |
| unverified fg on bg | 5.9 | 4.5 |
| calm fg on bg | 6.0 | 4.5 |
| confirm fg on bg | 6.8 | 4.5 |
| unsupported fg on bg | 7.0 | 4.5 |
| ink on each status bg | at least 15 | 4.5 |
| haunt / unverified / calm / confirm / unsupported edge on surface | 3.6 / 3.5 / 3.4 / 4.1 / 3.2 | 3.0 |
| accent (focus ring) on canvas and surface | 5.4 / 6.1 | 3.0 |

  This is test arithmetic on colour values, not money, so `no-model-math.md` is unaffected. The documented values are compared after rounding to one decimal. A mismatch fails the test; per R2.6 the doc is corrected.

### Reduced motion
- **CSS.** The existing `@media (prefers-reduced-motion: reduce)` block already sets `animation: none !important` and 0ms transitions and holds static glow. Additions:
  - `.fog { transition: none; }` (the 900ms opacity transition is not covered by `transition-duration: 0ms` when a utility sets `transition-property` later; the rule is `!important`).
  - `.animate-spin` replaced by a static ring and `Exporting…` text through a `motion-reduce:` variant on `ApprovalCard`.
  - Drawer and tablet panel: `animation: none` on `.calc-panel` and `.side-panel`.
  - `html { scroll-behavior: auto }`.
- **JS.** `grep` for `requestAnimationFrame`, `.animate(` and `scrollIntoView({ behavior: 'smooth' })` in `apps/web`. Any hit reads `useReducedMotion()` or uses `behavior: 'auto'`. A source-scan test (`no-js-animation.test.ts`) fails on a hit outside `useReducedMotion.ts`.
- **E2E.** `page.emulateMedia({ reducedMotion: 'reduce' })`, then for a haunted notice read computed styles: `animationName === 'none'` on `.glow-haunt`, `.glow-unverified`, `.fog`; `boxShadow` is not `none` and contains the static values; `transitionDuration` is `0s` on `.fog` and `.line`. A second run with `no-preference` asserts the animation names are `pulse-h`, `pulse-u` and `fog-drift` (so the test cannot pass by the animations never existing). Toggling the emulation on the same page checks R3.7.

### Empty inbox
- `app/page.tsx` renders `EmptyInbox` when `listNotices()` is empty. The amount-at-stake header is rendered only when at least one notice has a computed figure; otherwise the header shows the title and a caption, no `Figure`. This follows `Figure`'s rule that no provenance means no number, and avoids `$0.00` implying a check ran.
- Primary pill: `Try a specimen` (a form POST to `/api/specimens`, so it works without JavaScript). `Upload a notice` switches to the secondary style while the list is empty. The phone sticky bar mirrors the same choice.
- The specimen card is the real component, `aria-hidden="true"` with `inert`, so it is neither read nor focusable.

### Unsupported compound rate
- **Source of truth.** `calculate_duty` returns `status: "unsupported"` when the engine cannot compute the rate. `compareFigures` already yields `state: 'unsupported'`, which `assess.ts` maps to `computed: null`. This spec closes the display and draft gaps; it does not change the engine.
- **Fixture.** A test notice with a line whose rate text is a compound form the engine rejects. The unit tests use `rateText` directly (engine returns unsupported). The e2e test uses a recorded extraction fixture in `packages/notice-extract/fixtures/` for a synthetic notice (SPECIMEN-stamped, entry number invented) with one line at `rateText: "2.4¢/kg + 5%"` where the unit is missing or unparsable, so `calculate_duty` reports unsupported. If no real HTS line yields unsupported in the index, the fixture uses a rate text with a condition the parser does not model (e.g. `"1.5¢/kg + 4.5% (see note)"`), and the task records which one was used.
- **UI.** `UnsupportedLine` renders, in the recomputed cell: `—` with `aria-label="Not computed"`, then the sentence in `caption` text, always visible. The stated figure keeps its `stated` tag. The difference cell renders `—`. No pill other than `⊘ Not checked`.
- **Notice caption.** Counted from the lines in state `unsupported`: "N line(s) not checked and counted as stated." The count is a plain integer and not money.
- **Draft.** `draft-builder.ts` filters lines with state `unsupported` or `confirm` out of the claims and returns `skipped: { n, reason }[]`. The Exorcise page shows "1 line was left out because duty-engine cannot check its rate." The skipped list is not part of the hashed draft body, so it cannot affect approval.
- **Drawer.** `calcOf` throws for non-computed figures. For unsupported lines the drawer is built from a `{ unsupported: true, rateText, hts, edition, reason }` shape and shows no formula block, no `Match`/`Mismatch`.
- **Explanation guard.** `explain.ts` already has an `unsupported` sentence. The guard test confirms it has no digits.

### Odd uploads
- **Single checker.** `checkUpload(bytes, { declaredType? })` extends `checkFile` in `intake.ts` and returns `{ ok: true, mime, width?, height? }` or `{ ok: false, status, code, error }`. Order: empty (422), size (413), type by magic bytes (415), then for images the header parse (`image-info.ts`) for pixel count (422, `too_many_pixels`). The PDF path has no pixel check. `intake.ts` and `/api/inbound` both call it.
- **Header parsing.** PNG: IHDR width and height at bytes 16 to 24. JPEG: scan markers for the first SOF0 to SOF15 (excluding DHT, DAC, DNL) segment. Anything malformed returns `null` and is rejected as "not a readable image". No new dependency.
- **Aspect.** Not a rejection rule. `image-info` exposes the ratio so the extraction step can decide to downscale. Extraction already receives bytes; a `prepareForModel(bytes)` in `notice-extract` limits the longest side to the model's input limit with the aspect ratio kept. Where the repo has no image resizer, the task records that and the chosen approach (Playwright Chromium canvas, already a dependency, behind the web layer only for the copy sent to the model). The stored original is never replaced.
- **Client pre-check.** `Dropzone` rejects a file with `size > MAX_BYTES` before sending, to avoid uploading 50 MB to get a 413. The server check stays the authority. The client constant is imported from a shared `lib/limits.ts` that has no `node:` imports.
- **Messages.** `upload-messages.ts` holds every string, so the e2e tests quote the same constants. HEIC is detected by the `ftyp` box with `heic`, `heix`, `mif1` brands.
- **Error region.** `<p role="alert">` already exists. It gets `id`, the input gets `aria-describedby` pointing to it while an error is shown, and `aria-invalid`. Focus is not moved.
- **Stored files.** Rejected files are never written (the existing `notices-upload.test.ts` pattern checks the files dir).

### Tablet side panel
- Under `lg` (1024), the panel is hidden in flow. Selecting a line (a `?line=` link, as now) opens `SidePanelDrawer`, a `<dialog>` using the same class names and CSS as `CalcDrawer` (`.calc-drawer`, `.calc-panel`), so the slide and reduced-motion rules are shared and not duplicated.
- At `<md` the existing full-screen line view stays. A `matchMedia` check is not needed: all three presentations come from CSS plus a server-rendered `?line=` param. The `<dialog>` is opened with `showModal()` in an effect only when `matchMedia('(min-width: 768px) and (max-width: 1023px)')` matches. Resizing across a breakpoint closes or opens it accordingly.
- `LinePanel` content is unchanged; only the wrapper differs, so the tablet panel shows the same explanation, candidates and rulings, with the same citation rules.
